一个每天自动从 12 个量子物理（超导量子计算方向）学术期刊 RSS 源抓取论文、
按你配置的关键词 / 高亮作者筛选，并提供网页浏览与可导出报告（HTML / Markdown）的小工具。

> 适合：想每天自动汇总「自己关心的量子计算方向新论文」的研究者。
> 不需要任何第三方账号，本地跑、数据落在本地 SQLite。

> **关于你的配置与数据**（升级前必看）
> - `config/config.yaml` 是你**自己**的关键词 / 关注作者 / 云盘目录，**升级时不要覆盖它**；
>   仓库与 zip 包里只提供模板 `config/config.example.yaml`，程序在 `config.yaml` 不存在时会自动复制一份。
> - `data/`（数据库 `rnts.db`、报告、日志）不在仓库也不在包里，**升级永远不会动它**；
>   唯一会删数据的是保留期清理（未命中 31 天 / 命中作者 365 天 / 收藏永不清理）。
> - 推荐升级方式：只覆盖 `app/`、`templates/`、`static/` 与根目录脚本，**跳过 `config/` 和 `data/`**。

## 它是怎么工作的（重要，决定了你如何配置）

1. **全量入库**：每次抓取到的**所有**论文都会存进数据库，不是「先筛选再入库」。
2. **展示时实时筛选**：网页列表、导出的报告，都是在你查看的瞬间用**当前配置**重新匹配的。
   - 好处：你随时在 `config/config.yaml` 里增删关键词 / 作者，历史数据会**自动重新生效**，不用重抓。
3. **保留策略（滚动）**：
   - 未命中关键词 / 作者的原始论文：保留 **31 天**（控制数据库体积）。
   - 命中高亮作者的论文：保留 **365 天**（支撑「近一年作者精选报告」）。
   - **被收藏的论文永不清理**——收藏过的内容会一直保留。
4. **不会自动改写你的配置**：每日抓取只更新数据库和报告，**不会**再去动 `config/config.yaml`。
   想按字母顺序整理三个列表时，手动跑一次 `sort_config.bat`（见下）。

## 网页功能一览

顶部导航可在各页面间快速跳转（当前页高亮）：

| 页面 | 说明 |
|------|------|
| 📋 论文列表 | 默认**只显示命中关键词/作者的文献**（可取消勾选查看全部原始文献）；筛选 / 搜索 / 分页浏览；卡片右上角 ☆ 一键收藏；侧栏底部提供各类报告导出 |
| 👥 作者精选 | 近一年命中高亮作者的论文，国际 / 国内两个区块，**每位作者一个标签**，点击即切换该作者的论文 |
| ⭐ 我的收藏 | 收藏管理：**分组**（一篇可属多个分组，支持新建 / 重命名 / 删除）、**备注**、**挂本地 PDF**（上传副本或仅记录本机路径，在线预览） |
| 📊 统计 | 数量卡片、30 天趋势、来源分布、关键词 / 作者排行 |
| ⚙️ 设置 | RSS 源展示；关键词 / 高亮作者的网页端增删 |

收藏的 PDF 上传副本保存在 `data/attachments/`；本地路径方式不复制文件，文件被移动 / 删除后预览会提示失效。

导航栏右侧有两个操作入口：**「⟳ 手动抓取」**抓取全部源，**「⟳ 补抓 arXiv」**按选定日期单独补抓 arXiv（见下文）。

## 三分钟部署

> 前置：安装 Python 3.12+（Windows 安装时勾选 “Add python.exe to PATH”）。

1. 把整个 `RNTS` 文件夹放到任意位置（路径不要含中文/空格最佳）。
2. **Windows**：双击 `setup_env.bat` —— 自动建虚拟环境、装依赖、初始化数据库。
   **Linux / macOS**：终端运行 `bash setup_env.sh`。
3. **启动网页**：双击 `run.bat`（或终端 `bash run.sh`），浏览器打开
   **http://localhost:8000** 即可。

首次启动会自动建库并抓取当天论文（约 1 分钟）。

## 每日自动更新

有两种用法，选一种即可：

- **A. 常驻网页 + 内置调度（最简单）**
  一直开着 `run.bat`（或部署开机自启，见下），系统内置调度器每天 **08:00（本地时间）**
  自动抓取，无需额外设置。

- **B. 只更新数据 / 报告，不常驻网页（轻量，推荐给只想要每日报告的人）**
  用系统任务计划每天运行 `run_daily_task.bat` 即可（详见 **《操作说明_每日任务.md》**）。
  数据落在 `data/rnts.db`，报告落在 `data/reports/`，可复制到手机或云盘查看。

> 想让网页服务也开机自启：`powershell -ExecutionPolicy Bypass -File install_autostart.ps1`

## arXiv 抓取：双层结构 + 按日期补抓

arXiv（quant-ph）是本系统的主力源，它的抓取方式和其它 11 个 RSS 源不同，
按 arXiv 官方接口规范分**两层**抓取，结果自动按论文链接去重合并：

| 层 | 接口 | 抓什么 | 说明 |
|----|------|--------|------|
| 公告层 | `rss.arxiv.org/rss/quant-ph` | 当天该分类的全部新公告 | 一次请求搞定；含**完整摘要与完整作者列表**；与搜索 API 的限流互不影响 |
| 时间窗层 | `export.arxiv.org/api/query` | 最近 `arxiv_lookback_days` 天（默认 3）提交的论文 | 按提交日期回溯，补齐某天没开机而漏抓的论文 |

- **为什么分两层**：arXiv 对**搜索 API** 按出口 IP 限流（返回 429 或拖延不响应），
  而 RSS 公告源走另一条路径、不受影响。因此公告层是**高可用层**——
  搜索 API 被限流时，它依然能拿到当天该分类的全部新论文（可随时在
  `config.yaml` 的 arxiv 源下用 `rss_url:` 指定别的分类）。
- **不再有 50 篇上限**。时间窗层会在源配置的分类条件上追加 `submittedDate`
  日期区间并自动翻页取回区间内的**全部**论文。
- **回溯窗口**由 `schedule.arxiv_lookback_days` 控制（默认 3 天）。之所以回溯而不是
  只取当天：arXiv 的公告比提交时间晚约 1–2 天，周一早上还要覆盖上周五与周末的提交。
  重复抓到的条目由数据库按链接自动去重，多抓无副作用——**若某段时间没开机或 API
  长期被限流，把这个值临时调大（如 7），下一次成功运行就会把漏掉的日期一并补回**。
- **按日期补抓**：某天没开机、错过了当天的 arXiv 公告时，用顶部导航栏右侧的
  日期框 + 「⟳ 补抓 arXiv」按钮补齐。默认填昨天，抓取区间为
  `[选定日期-3, 选定日期]`。补抓只抓 arXiv、只增不删（不会触发保留期清理），
  同一天可以放心重复点，已入库的会自动跳过；被限流时会立即转用缓存、十几秒内返回。

> 日期口径按 **arXiv 提交日期（submittedDate，UTC）** 计算，不是「当天公告批次」，
> 所以想找「某天早上刷到的文章」时，选那天或再往前一天都能覆盖到（窗口本身已回溯 3 天）。
> 历史日期只能走搜索 API（RSS 公告没有历史存档），因此被限流时补抓只能返回缓存内容。

## 配置（config/config.yaml）

| 字段 | 说明 |
|------|------|
| `rss_sources` | 论文源（默认 12 个，已可用，一般不用改） |
| `rss_sources[].rss_url` | 可选：arXiv 的「当日公告层」地址。不填则按该源 `url` 里的 `cat:xxx` 自动推导（`cat:quant-ph` → `https://rss.arxiv.org/rss/quant-ph`）；想改抓别的分类时显式指定 |
| `keywords` | 关键词（标题 + 摘要匹配，大小写不敏感、单词边界） |
| `highlight_authors_1` | 国际高亮作者（报告里归为「国际组」） |
| `highlight_authors_2` | 国内高亮作者（报告里归为「国内组」） |
| `schedule.daily_fetch_time` | 每日抓取时间，默认 `08:00` |
| `schedule.arxiv_lookback_days` | arXiv 抓取的回溯天数，默认 `3`（每日抓取取 `[今天-N, 今天]`，网页端「补抓 arXiv」取 `[选定日期-N, 选定日期]`；`0` 表示只取当天） |
| `cloud_sync` | 可选：把报告自动复制到**你自己设定**的云盘目录（坚果云 / OneDrive 等）。默认关闭、目录留空 |

改完保存即可，历史数据会自动按新配置重新匹配。

### 在配置里写注释（不会丢）

三个列表都可以随手加注释，系统会原样保留（重排时注释跟着条目一起走）：

```yaml
highlight_authors_1:
# 德语区（变音字母 ü/ö/ä/ß 会自动兼容 Juergen / Joerg 等转写写法）
- Jürgen Lisenfeld  # Ulm
- Jörg Wrachtrup    # Stuttgart
- Alexandre Blais
```

- 条目**上方**的注释行、条目**行尾**的 `# ...` 都会跟着该条目
- 只有 `#` 前面是空白时才算注释，所以名字里紧挨着的 `#` 不会被误伤

### 作者名匹配规则

大小写不敏感，另外兼容以下几种常见写法差异：

| 情况 | 示例（配置里写的 vs 论文里的） |
|------|------|
| 变音字母 | `Jürgen Lisenfeld` ↔ `Juergen Lisenfeld` / `Jurgen Lisenfeld` |
| Unicode 分解 | `ü`（预组合）↔ `u¨`（分解），两种码位都能对上 |
| 首字母缩写 | `R. J. Schoelkopf` ↔ `RJ Schoelkopf` |
| 姓名顺序 | `Han Wang` ↔ `Wang Han` |

匹配是**整名比较**，不会出现 `Han Wang` 误匹配 `Zihan Wang` 这种子串误伤。

### 手动整理列表顺序（sort_config.bat）

需要把三个列表按字母排序时双击 `sort_config.bat`（等价命令 `python sort_config.py`）：

- 写回前自动备份为 `config/config.yaml.bak`
- 排序为大小写、变音不敏感：`Jürgen` 按 `jurgen` 参与排序，不会跑到列表末尾
- 加 `--check` 参数只预览会怎么变、不动文件：
  `python sort_config.py --check`

### 云同步（可选，默认关闭）

系统**不内置任何云盘路径**，需要同步时由你自己指定：

1. 打开 `config/config.yaml`，把 `cloud_sync.dir` 改成你自己的同步目录，例如 `D:/Nutstore/1/RNTS_报告`；
2. 把 `cloud_sync.enabled` 改成 `true`；
3. `cloud_sync.formats` 选择要同步的格式，默认 `html` + `md`（手机端看建议 `html`）。

不想改配置文件的话，也可以用环境变量设置（多机部署 / Docker 更方便）：

```powershell
setx RNTS_CLOUD_SYNC_DIR "D:\Nutstore\1\RNTS_报告"
setx RNTS_CLOUD_SYNC_ENABLED 1
```

> 目录留空或 `enabled: false` 时不做任何同步，论文抓取与报告生成完全不受影响。

## 产出的报告

每次抓取后生成在 `data/reports/`：

- `RNTS_近一月更新报告.html` / `.md` —— 最近 30 天、按当前配置命中的论文，按日期分天列出
- `RNTS_近一年作者精选报告.html` / `.md` —— 最近 365 天、命中高亮作者的论文，按作者分组

## 其他部署方式

- **Docker**：`docker compose up -d --build`，访问 http://localhost:8000
  （配置与数据通过卷持久化到 `./config` 和 `./data`）

- **数据迁移**：把旧机器的 `data/rnts.db` 复制过来即可（去重靠 `link` 唯一约束）。
